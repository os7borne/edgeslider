## What this is

EdgeSlider is a tiny macOS menu bar app (Swift, SwiftUI + AppKit, no Xcode project). Rest one finger on the **left edge** of the
trackpad and slide for **brightness**, **right edge** for **volume** (swappable). A pill indicator slides in from the screen edge,
the trackpad gives haptic ticks, and the pointer stays put. Bottom-edge swipe skips tracks. Free, GPL-3.0-or-later, signed and notarized.

### How input works (and why it is built this way)

- Raw touches come from the **private `MultitouchSupport.framework`** (`dlopen`; `MTDeviceCreateList`, `MTRegisterContactFrameCallback`, `MTDeviceStart`).
  Touch struct is read by raw byte offsets (stride 96; `identifier` at 16, `state` at 20, normalized x/y floats at 32/36). Only `state == 4` (touching) counts.
  The callback is a C function pointer on a high-frequency background thread and calls `controller.update(touch:count:)` **directly** (hopping to main added lag).
- Only **single-finger** frames are handled (`count == 1`).
- **Landing rule (anti false-trigger):** a finger only counts if it *landed* inside an edge zone (`edgeWidth`, default 7%), then must move vertically
  past `deadZone` (0.035 of pad height, constant in main.swift) before it engages. Drifting inward past 1.8x edge width before engaging cancels it.
  Optional `bottomQuarterOnly` requires landing at y < 0.25. Sliding is **relative** (no jump on touch-down).
- **Pointer pinning:** on engage, `CGAssociateMouseAndMouseCursorPosition(0)` plus `CGWarpMouseCursorPosition(anchor)` every frame. No Accessibility permission.
- **Output is coalesced:** `push()` stores only the newest value and applies it on a serial `userInteractive` queue (Volume/Brightness calls are slow). The HUD is
  updated from the touch data first, via its own coalescer, so the visual never waits on hardware. Volume caches the device ID and only touches mute when crossing 0.
- **Volume** uses property `'vmvc'` (virtual main volume) on the default output device. **Brightness** uses `DisplayServicesGetBrightness/SetBrightness` on the main display (built-in display only).
- **Haptics:** `NSHapticFeedbackManager` (no intensity API). Off / Light (tick every 10%, `.alignment`) / Strong (every 5%, `.levelChange`); bump at 0% and 100%.
- **HUD pill:** borderless window, vertical pill on the screen edge matching the slider side; icon + optional percent + white fill. Slides in 0.22s, holds 0.8s after the last
  update, slides out 0.2s; a generation counter prevents a stale fade from hiding a live pill. Main display only.
- **Media strip:** touch landing at y < 0.10 outside the edge zones; horizontal travel > 0.22 of pad width (vertical drift < 0.2) fires **once** per swipe:
  `NSEvent.systemDefined` media key 17 (next) / 18 (previous) posted to `cghidEventTap`.
- **Quick Mute:** tap (< 0.6s, movement < 0.06) in the top-right corner (x > 0.86, y > 0.86), twice within 0.7s (lift to lift), toggles the output mute and shows the volume pill.
  **Off by default**: with Tap to Click on, taps also click under the pointer and that cannot be blocked without an event tap (Accessibility permission).
- **Switch Output (1.3, build 3, built and notarized 2026-11-03, release not yet published):** double-tap the top-left corner (x < 0.14, y > 0.86, same tap rules as Quick Mute, own timestamp) cycles `AudioOutput.outputs()` (CoreAudio; output channels, not hidden, aggregate/virtual skipped) and sets default output + system output. `DeviceHUD` shows icon + name at top centre. Setting `switchOutput`, **off by default** (same Tap to Click caveat). Built and compiled; **not tested on hardware** (Bluetooth/HDMI cycling unverified). Site not updated yet; add a card when 1.3 ships.
- **Corner tap tuning (2026-11-03, hardware-verified on the owner's Mac):** the original limits (0.25s, 0.025, 0.45s) failed in real use. Taps on the extreme corner tip (y or x ~1.0) are sensed poorly: contact lingers 0.4-3s and the centroid jumps ~0.05. Taps ~1 cm in from the tip last 0.05-0.15s with gaps of 0.2-0.3s. Logging showed 12/12 double-taps firing with the relaxed limits. Fixed in 1.3.1 (build 4, built and notarized 2026-11-03, release not yet published); 1.3 shipped with the old limits.
- **Menu bar glyph:** template `NSImage` drawn in code (trackpad outline + two bars); dims when paused; tinted orange (`contentTintColor`) when an update is waiting.

### Settings and defaults

## Build, release, update pipeline

```sh
./build.sh            # dev build: ./EdgeSlider.app, ad-hoc signed, host arch
./build.sh install    # dev build + copy to /Applications (kills running EdgeSlider)
./build.sh release    # universal, Developer ID signed (inside-out), notarized, stapled -> dist/EdgeSlider.zip
scripts/make-appcast.sh   # signed Sparkle feed -> site/appcast.xml (EdDSA key read from the login Keychain)
scripts/screenshots.sh    # regenerate docs/images/*.png
swift scripts/make-social.swift   # regenerate docs/images/social-preview.png (upload manually in GitHub settings)
```

- `build.sh` env overrides: `VERSION`, `BUILD`, `FEED_URL`, `EXTRA_PLIST`, `BUNDLE_ID`. Release needs `IDENTITY`, `KEY_PATH`, `KEY_ID`, `ISSUER` from git-ignored `release.local.env`
  (details in the `apple-distribution` skill; notarization uses the App Store Connect API key, same as Ozmail/Cal).
- **Always compiled with `-target <arch>-apple-macos13.0`**; without it the binary targets the host OS (27) and will not run on older Macs.
- Sparkle 2.10.1 is pinned and checksum-verified by `scripts/fetch-sparkle.sh` into git-ignored `vendor/`. XPC services are removed (app is not sandboxed).
  Sparkle's MIT notice is copied into the app's Resources.
- **Sparkle EdDSA key** is the user's single login-Keychain key, shared with Ozmail and Cal. The public key is in `build.sh`/Info.plist. **Back it up; losing it strands every installed copy.**
- The release zip is always named **`EdgeSlider.zip`** so `releases/latest/download/EdgeSlider.zip` is a stable link; the appcast enclosure points at `.../releases/download/v<version>/EdgeSlider.zip`.
- **To cut a release:** bump `VERSION` and `BUILD` in `build.sh` (BUILD must increase), add `notes/<version>.md` and a CHANGELOG entry, `./build.sh release`,
  `scripts/make-appcast.sh`, `gh release create v<version> dist/EdgeSlider.zip --target main --title ... --notes-file notes/<version>.md`, then push `site/` so Vercel serves the new `appcast.xml`.
  Verify: the served appcast equals `site/appcast.xml`; the downloaded zip has the same SHA-256 as `dist/`; `spctl -a -vv` says "Notarized Developer ID".
- Bundle ID was changed from `local.edgeslider` to `vc.osborne.edgeslider` on 2026-11-02 (settings reset once, login item must be re-enabled).

- Feed: `https://edgeslider.osborne.vc/appcast.xml`. `SUEnableAutomaticChecks` is true. **Sparkle never schedules checks more often than hourly**, regardless of `SUScheduledCheckInterval`.
- Gentle reminders: if an update is found while the user is not looking, no window pops; the menu bar icon turns orange and the panel shows an "Install" banner, which calls the normal Sparkle flow.

## Decision log (why things are the way they are)

- **Hold-to-seek on the bottom strip was built, then removed.** Browsers and YouTube do not map fast-forward/rewind media keys to seeking; only skip remained. The strip now fires next/previous once per swipe.
- Skipping needs a player with a queue (Music, Spotify, playlists). A lone YouTube video does nothing. macOS may prompt for permission when media keys are first sent (unverified).
- Quick Mute defaults off (Tap to Click side effect). Tap-to-Play/Pause was deliberately not built for the same reason plus false triggers.
- Distribution is **outside the App Store** (private frameworks). Developer ID + notarization + Sparkle, matching the Ozmail/Cal pattern.
- License chosen by the user: **GPL v3** (headers say or-later). Sparkle is MIT-compatible.
- Open-source cleanup done: LICENSE, README with generated screenshots, CHANGELOG, CONTRIBUTING, issue templates, folder restructure, repo description/homepage/topics set via `gh`.
- Notarization IDs were moved out of `build.sh` into `release.local.env` before anything was published.
